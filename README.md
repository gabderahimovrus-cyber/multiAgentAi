# Multi-Agent AI Studio

Локальное desktop-приложение на Python для работы с автономной многоагентной средой через Ollama. Интерфейс по умолчанию русскоязычный и ориентирован на единый проектный чат, где пользователь пишет одну задачу, а система сама подключает Coordinator, Architect, Developer, QA, Researcher, Writer и других агентов.

## Запуск

1. Установите Python 3.11+.
2. Установите и запустите Ollama: `ollama serve`.
3. Скачайте хотя бы одну модель, например: `ollama pull llama3.1`.
4. Запустите приложение:

```bash
python main.py
```

Также доступен альтернативный вход:

```bash
python app.py
```

## Новая концепция среды

- **Единый общий чат проекта.** Пользователь больше не обязан выбирать отдельного собеседника. Сообщение отправляется в общий чат, а сервис оркестрации выбирает участников обсуждения.
- **Внутренний канал агентов.** Coordinator делегирует работу другим агентам, агенты отправляют отчёты обратно, а все внутренние сообщения сохраняются и отображаются во вкладке наблюдения.
- **Коллективный ответ.** Итоговый ответ формируется после вкладов выбранных агентов и добавляется в историю общего чата как ответ команды.
- **Журнал решений.** Если модель отдаёт reasoning-подобное поле, оно попадает в отдельный лог. Если reasoning недоступен, агенты всё равно логируют решения, статусы, делегирование, модельные запросы и действия.
- **Активные состояния агентов.** Для каждого агента хранится и отображается состояние: ожидает, думает, обсуждает задачу, работает с файлами, выполняет задачу, завершил задачу или ошибка.

## Интерфейс

Основное окно разделено на четыре зоны:

1. **Левая панель** — чаты и проекты. Можно создавать, переименовывать, архивировать и удалять чаты, переключаться между историями обсуждений и создавать проекты.
2. **Центральная область** — единый общий чат выбранной сессии.
3. **Правая панель** — список агентов и карточка выбранного агента. В карточке доступны редактирование имени, роли, модели, системного промпта, температуры, разрешений, просмотр памяти и истории действий, клонирование и удаление.
4. **Нижняя область наблюдения** — события системы, внутренние сообщения агентов и reasoning/решения с фильтрацией по тексту, типу события и id агента.

## Модели Ollama

- Поддерживается локальный Ollama endpoint и удалённые Ollama-серверы.
- Endpoints задаются в верхней панели через `;`, например:

```text
http://127.0.0.1:11434;http://192.168.1.20:11434
```

- При обнаружении моделей рядом с названием отображается источник: `model:tag [local]` или `model:tag [host:port]`.
- В настройках есть глобальная модель по умолчанию. Новые агенты используют её автоматически, но каждый агент может иметь собственную модель.
- Агенты могут логировать предложение сменить модель; пользователь подтверждает изменение через интерфейс, сохраняя настройки агента.

## Возможности и разрешения агентов

Каждый агент получает в системный контекст описание возможностей и текущих разрешений. Разрешения отображаются переключателями с подсказками:

- чтение, запись и удаление файлов;
- выполнение скриптов;
- создание и удаление агентов через запрос подтверждения;
- использование сети;
- чтение и запись Git;
- загрузка плагинов;
- управление моделями;
- создание задач.

Опасные операции остаются выключенными по умолчанию и должны явно включаться пользователем.

## Архитектура

```text
multiagent_ai_studio/
  app.py                  # сборка зависимостей и запуск UI
  core/                   # ядро: агенты, БД, память, задачи, плагины, файлы, шина сообщений
  providers/              # реестр провайдеров и multi-endpoint Ollama provider
  ui/                     # desktop UI
  i18n/                   # русская локализация и будущие языки
main.py                   # основной вход
app.py                    # альтернативный вход
```

Ключевые компоненты:

- `AgentService.run_project_chat()` запускает коллективное обсуждение общего чата.
- `AgentMessageBus` публикует внутренние сообщения агентов.
- `Database` хранит агентов, чаты, сообщения, внутренние сообщения, логи, задачи, проекты и настройки.
- `OllamaProvider` обнаруживает модели на локальных и удалённых endpoints и направляет генерацию на endpoint выбранной модели.


## Безопасность

Опасные операции отделены разрешениями агента: выполнение скриптов, доступ к сети, запись в Git, удаление файлов, создание/удаление агентов и загрузка плагинов. Самомодификация ядра должна проходить через явные предложения изменений и пользовательское подтверждение.
